# Motion Garden 部分人體追蹤

三款體感遊戲使用各自需要的關鍵點。頭部可以出框。拔蘿蔔的頭部動畫只在臉部訊號可靠時跟隨，缺少時回到中立。MediaPipe 模型、置信度設定與資料新鮮度檢查沿用既有管線。出框、低置信度或幾何無效的點不參與動作估計。

| 遊戲 | 最少需要看見 | Full Tracking | Partial Tracking |
| --- | --- | --- | --- |
| 拔蘿蔔 | 雙肩、雙髖、雙膝可供部分校準 | 使用已校準腿側的髖、膝、踝角度 | 使用已校準的雙側大腿投影訊號 |
| 莓果大豐收 | 雙肩、雙髖可延續橫移。伸腳和初始站立參考至少需一側膝頭 | 以可靠的髖、膝、踝計算伸腳 | 按側使用可見大腿，另一側仍可用精確幾何。該側膝頭失去時暫停該腳 |
| 摘蘋果 | 雙肩、雙髖和至少一隻手腕可開始採摘 | 兩隻手腕各自可採摘與放置 | 只有可見手腕可確認手勢 |

Tracking Lost 會在必要部位缺失或來源過期時停止受影響的動作。莓果或蘋果個別肢體失去訊號時，保留仍然可靠的肢體控制。鏡頭訊息會指出需要入鏡的部位。暫停清除舊輸入，恢復需可靠的新資料。

## 莓果大豐收

每側大腿向量使用同側髖至膝，投影至軀幹的向下與橫向軸。外展角及歸一化外移量要一起超過自然站立基準與啟動門檻，並保持 110 ms 才確認。影像橫向偏移提供交叉核對。可見支撐腿須保持在自然基準附近，避免側傾或雙膝固定時的移重被當成踢腳。收回門檻較低，保持 100 ms 才確認收腳。大腿估計以連續 0–1 控制現有 3D 兔腿。腳部接觸仍取用虛擬兔腳的骨骼投影，沿用目標樹、收腳及冷卻規則。

橫移來自髖中心，與同側局部髖膝差向量分開處理。整體平移不產生伸腳訊號。每側模式切換後重新確認收腳，避免正伸出時恢復踝點就重複得分。軀幹無法追蹤時保持兔子的畫面位置與原有站立參考。

## 拔蘿蔔

部分模式以雙側髖至膝的影像向量投影至軀幹軸，按肩寬歸一化。主要訊號是雙側大腿向下投影的縮短程度，外展提供較小的輔助訊號。兩側需要有相容的姿勢，側傾及退化幾何會拒絕。這是無單位的相對動作訊號。真實膝角只在有可用髖、膝、踝資料時顯示。

自然站立及舒服淺屈膝分別取樣。全程看見腳踝時保留原有角度流程，也可在同一輪有效樣本中建立備用的大腿基準。如果兩個姿勢在影像投影中太相近，應調整取景或使用可辨識的舒服動作幅度。只有部分基準的會話沿用已校準的訊號，重新設定可建立精確角度範圍。雙基準可靠時，模式交接等待穩定站立，再使用另一項校準。原有保持時間、兔子同步、抓握、入籃及五輪規則沿用。

## 桌面 16:9

固定的 1600×900 邏輯畫面等比縮放至窗口。遊戲 HUD、校準介面及遊戲說明沿用桌面配置。說明旁的 9:16 動作示範保留其影片比例。

## 驗證範圍

自動化用合成 MediaPipe 關鍵點檢查頭部及腳踝出框、單側踝或膝缺失、橫移、精確與部分模式交接、過期輸入及攝像頭生命週期。Chrome Playwright 驗證實際 Phaser／Three.js 畫面、碰撞及分數。

```sh
QA_PARTIAL_ONLY=1 npm run qa:carrot-game
npm run qa:berry-camera
npm run qa:apple
npm run qa:desktop-layout
```

先啟動開發伺服器，再用 `QA_URL` 指定網址、`QA_OUTPUT` 指定絕對證據路徑。
